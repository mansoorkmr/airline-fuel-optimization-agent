## Overview
This project implements a proof-of-concept (POC) Airline Fuel Optimization Agent
designed with institutional-grade architecture and clear operational semantics.

The system analyzes flight plans, derived weather signals, and aircraft
performance data to recommend fuel-efficient cruise altitude adjustments for
airline operations.

The solution emphasizes determinism, auditability, and clean separation between
business logic and infrastructure.

---

## Architecture
The system follows a clean, layered architecture:

- **Domain** – Core business entities (Flight, Aircraft, Weather)
- **Ingestion** – Deterministic loading of flight and reference data
- **Services** – Weather and aircraft performance abstractions
- **Optimization** – Fuel consumption modeling and decision logic
- **Workflow** – Strands-compatible orchestration layer
- **MCP Integration** – Operational recommendation publishing
- **Audit & Reporting** – Deterministic decision records

All layers are designed to be independently testable and extensible.

---

## AWS Strands
Workflow logic is implemented using a **Strands-compatible abstraction** that
maps directly to AWS Step Functions.

In this POC, AWS Strands is represented conceptually rather than via a concrete
SDK dependency. AWS services are intentionally **not hard-coded** in the core
business logic to preserve portability across local, HPC, and cloud execution
environments.

This design allows the same deterministic workflow to execute:
- Locally for development and testing
- On HPC infrastructure using Slurm job arrays
- In AWS using Lambda and Step Functions

---

## Mission Control Protocol (MCP)
Operational recommendations are emitted using a Mission Control Protocol (MCP)
message format that is:

- Versioned
- Deterministic
- Audit-friendly
- Suitable for downstream airline operational systems

MCP messages include the original plan, optimized plan, projected fuel savings,
and decision rationale.

---

## Execution Modes
The system supports multiple execution environments without code changes:

- **Local execution:** 
  `python -m app.main`

- **HPC execution:** 
  Slurm batch and array jobs (one flight per task)

- **AWS execution:** 
  AWS Lambda orchestrated via Step Functions

## Sample Output
Example outputs generated by the system include:

- `output/*_mcp.json` – Operational recommendation messages
- `output/*_audit.json` – Deterministic audit reports

These artifacts capture original vs. optimized plans, fuel savings, and
decision rationale.

## Scope & Limitations
The following design choices are **intentional and documented**:

- **Vertical (altitude-based) routing optimization only;** lateral routing is
  intentionally out of scope for this POC.
- Weather inputs are represented via **derived operational signals**
  (e.g., wind components).
- **Raw METAR/TAF parsing is intentionally out of scope;** the system consumes
  abstracted weather features, as is standard in airline optimization systems.
- Aircraft performance and weather data are mocked to ensure deterministic,
  reproducible behavior.
- No real-time data feeds or external APIs are invoked.

---

## Future Improvements
The architecture is designed to support future extensions, including:

- Integration of real METAR/TAF parsing and live weather feeds
- Lateral routing optimization using airspace and waypoint graphs
- Operational recommendations such as **delay or aircraft re-dispatch**
  based on downstream constraints
- Cost index and fuel price sensitivity modeling
- Multi-objective optimization (fuel, time, emissions)
